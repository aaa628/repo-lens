# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

RepoLens: a Next.js app that takes a public GitHub repo URL and produces an interactive architecture graph, a "bug radar" with exact `file:line` findings, and a guided onboarding tour. See README.md for the user-facing overview.

## Commands

```bash
npm run dev                 # dev server (http://localhost:3000)
npm run build               # production build (also type-checks)
npm run typecheck           # tsc --noEmit — the fastest correctness check
npm run ingest -- <github-url> [--prompt out.txt]
                            # run Stages 1–2 only (no LLM, no key): prints selected files + import edges,
                            # optionally writes the exact Stage 3 prompt
npm run demos -- <github-url> <slug> [--analysis demos-src/<slug>.json --model "..." --note "..."]
                            # write public/demos/<slug>.json: full pipeline (needs a key), or re-ground a stored analysis
```

There is no test suite and no linter configured. Verify changes with `npm run typecheck`, `npm run build`, and `npm run ingest` for pipeline changes. UI changes need a browser check (the `?demo=<slug>` deep link loads a workspace without an API key).

Env (see `.env.example`): `LLM_PROVIDER` (`anthropic` default | `openai`), `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL` (default `claude-opus-5-5`), `ANTHROPIC_EFFORT` (default `medium`), `OPENAI_API_KEY`/`OPENAI_MODEL`, `GITHUB_TOKEN` (optional, raises the rate limit).

## Version caveats

Most dependencies are newer than typical training data. Check `node_modules` typings before assuming an API:
- **Next.js 16**: `AGENTS.md` is regenerated by `next dev` and says to read `node_modules/next/dist/docs/` before writing Next-specific code. Don't delete it; it comes back.
- **@xyflow/react 13**: dark mode is `forceColorMode`, not `colorMode`. `useNodesInitialized` never reported ready here, so camera readiness comes from ReactFlow's `onInit`.
- **lucide-react 1.x**: no brand icons (no `Github`) and no `*Alert*` icons. Grep `node_modules/lucide-react/dist/lucide-react.d.ts` for `declare const <Name>:` before using an icon.
- **Tailwind 4**: there is no tailwind config file. Theme tokens live in `@theme` in `app/globals.css`.
- **zod 4**, **TypeScript 7**, **Anthropic SDK 1.x** (structured output via `betaZodOutputFormat` from `@anthropic-ai/sdk/helpers/beta/zod`).
- `package.json` has `"type": "module"`, required for top-level await in `scripts/*.ts`, which run via `tsx`. tsx needs esbuild's install script, which is approved under `allowScripts`.

## Architecture

### Analysis pipeline (server)

`app/api/analyze/route.ts` is a POST endpoint that streams **SSE frames**: `event: progress` (`ProgressEvent`), then exactly one `event: result` (`AnalysisResult`) or `event: error` (`{message}`). It holds an in-memory per-instance cache keyed by `owner/repo`, and checks LLM credentials before doing any work. The client parser is `streamAnalysis` in `components/RepoLens.tsx`.

`lib/analyzer.ts#analyzeRepo` orchestrates the pipeline. Each stage is exported separately so the scripts can run parts of it:
1. **Ingest** (`lib/github.ts`): repo meta + recursive tree; `isNoise`/`isTest` filtering; `scoreFile` heuristics; `selectFiles` does a two-pass pick (best file per "area" first, then by score) under caps: ~28 files, 150 KB total, 24 KB per file, plus per-dir/per-area/per-top-level limits. Contents come from `raw.githubusercontent.com`. Selection quality is tuned in `scoreFile`, `areaOf` and the caps; check changes with `npm run ingest` against a few repos.
2. **Parse** (`lib/parser.ts`): regex import/export extraction for JS/TS, Python, Go, Rust, JVM and Ruby, resolved against the **full tree path set**, not just fetched files. Produces the file→file `ImportGraph`.
3. **Synthesize** (`lib/llm/`): `index.ts` picks the provider from `LLM_PROVIDER`. The prompt is `SYSTEM_PROMPT` + `buildUserPrompt` (outline, import graph, exports, line-numbered file contents). Both providers return `LlmAnalysis`, validated by `LlmAnalysisSchema` in `lib/types.ts`. Optional fields in that schema must stay `.nullable()` (not `.optional()`) so it works with both providers' strict JSON modes. Anthropic uses a beta stream with server-side refusal fallbacks (`fallbacks: "default"`).
4. **Ground** (`groundAnalysis`): the LLM output is not trusted as-is. It drops nonexistent paths; maps files to nodes (exact path beats longest directory prefix) to compute `fileCount`; marks edges `grounded` when the import graph supports them and adds missed import edges; drops bugs that cite files outside the tree, sets `verified` and attaches real source `context` lines; relocates `keySnippet` to the real lines (`startLine`). `LlmAnalysis` (model output) and `AnalysisResult` (grounded output the UI consumes) are deliberately different types.

### Instant demos

`public/demos/*.json` are `AnalysisResult`s served statically. Their Stage 3 input in `demos-src/*.json` was hand-authored (no LLM key was available) from the files the pipeline fetched. Regenerating with `--analysis` re-runs ingest + grounding live against GitHub. The demo list shown on the landing page is `lib/demos.ts`.

### UI (client)

- `components/RepoLens.tsx`: phase state machine (landing → loading → workspace), SSE consumption, `?demo=` / `?repo=` deep links.
- `components/Workspace.tsx` owns all interaction state: `mode` (architecture | bugs | tour), selected node/bug, tour step. It derives `highlight` (node ids kept bright; others dimmed) and `activeNodeId` per mode. Camera moves are requested by bumping a `Focus` **nonce**; `CameraController` in `GraphCanvas` reacts to nonce changes. Compare nonces, not "first run" flags: StrictMode double-runs effects in dev.
- `components/GraphCanvas.tsx`: dagre LR layout, custom `arch` node and `flow` edge (smooth-step paths). The **execution-trace animation** comes from `schedule()` (BFS levels from entry nodes → per-edge delay and per-node ignite time; timing constants `STEP`/`DRAW`). It is driven by CSS keyframes in `globals.css` (`edge-trace` via `pathLength=1` dashoffset, `node-ignite`, `tile-ignite`) plus SMIL sparks started with `beginElementAt`. Replays work by bumping `run`, which is used as a React `key` so animated elements remount. Respects `prefers-reduced-motion`.
- `components/Inspector.tsx`: the three right-panel modes. `CodeBlock.tsx` lazy-loads Shiki on the client, with real line numbers via a CSS counter (`--start`) and a highlighted line.
- `lib/export.ts`: Markdown report + Mermaid export. Solid arrows are grounded edges, dotted arrows inferred.

### Visual design

The palette is black / white / signal red: the `--color-signal-*` scale and `bg`/`panel`/`line`/`fg`/`muted`/`dim` tokens in `app/globals.css`. Don't reintroduce other accent hues. Layer and severity colours are centralised in `lib/ui.ts` (`LAYER_STYLE`, `SEVERITY_STYLE`) and reused by the graph, minimap, legend, inspector and export. Layers are distinguished by icon as well as tint (`LAYER_ICON` in `GraphCanvas.tsx`). Workspace layout is full-viewport with no page scroll; only the inspector panel scrolls.
